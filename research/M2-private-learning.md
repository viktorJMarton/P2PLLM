# M2 — protected cooperative learning

Pin Qwen base, LoRA/update representation, task/data provenance and held-out evaluation. First prove ordinary learning changes quality as intended; then compare protected round with equivalent reference. Keep individual records and updates hidden according to selected profile. If DP claimed: define record/user protection, clipping/noise, epsilon/delta accountant and repeated rounds. Secure sum alone is insufficient against small cohort or difference attacks.

Measure held-out quality/regressions, update error vs reference, convergence, bytes/round, dropout behavior, memory, time/energy and leakage analyses. Secure aggregation may conflict with per-update poisoning inspection; do not claim both without a concrete design.

Release gate: useful cooperative update, local acceptance/rejection, crash-safe activation/rollback, no silent individualized update exposure, independently reviewed profile. Desktop training does not satisfy Android training requirement without mobile feasibility evidence or explicit scope revision.
